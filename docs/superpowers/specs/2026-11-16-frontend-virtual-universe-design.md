## 1. เจตนาและเหตุผล

ทีมแบ่งงาน: ผู้ใช้ทำหน้าเว็บ เพื่อนทำหลังบ้านที่เป็น Chatbot แล้วนำมาประกอบกัน **[ยืนยัน]**

ผู้ใช้ต้องการให้หน้าเว็บ **ใช้งานได้ก่อน** เพื่อเห็นภาพรวมเบื้องต้น จากนั้นจึงใส่ข้อมูลจริง รูป และต่อ Chatbot **[ยืนยัน]**

รอบแรกใช้แนวทาง **A: ครบทุกพื้นที่แบบเรียบ ๆ** — โครงโลกครบ เดินทางได้ทั่ว แชทเปิดได้ สลับภาษาได้ เอฟเฟกต์พอประมาณ แล้วค่อยเติมความอลังการ **[ยืนยัน]**

เหตุผลสำคัญ: กำหนดส่ง 20 พ.ย. 2569 23:59 ต้องมีเว็บที่ "ส่งได้" อยู่ตลอดเวลา ความสวยเพิ่มทีละชั้นบนของที่ใช้งานได้แล้ว

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมายรอบแรก**
- เปิดเว็บ → Intro 4–5 วินาที → เข้าโลก → เดินทางได้ครบ 5 พื้นที่
- Mini Map / District Navigator ใช้ได้ รู้ว่าอยู่ตรงไหน ไปที่ไหนได้
- หน้าต่างแชทเปิดได้จากทุกพื้นที่ พิมพ์ได้ แสดงข้อความ User/AI และแหล่งอ้างอิงได้ (ตอบด้วยข้อความจำลองจนกว่าหลังบ้านพร้อม)
- สลับภาษาไทย/อังกฤษได้ทั้งเว็บ
- ทุกช่องข้อมูลที่ต้องใช้ของจริงมีที่วางพร้อม และแก้ได้จากไฟล์ข้อมูลไฟล์เดียว
- ต่อหลังบ้านได้โดยแก้จุดเดียว + ตั้งค่า URL ใน `.env`

**ไม่ใช่เป้าหมายรอบแรก**
- เสียงของ AI (รอตัดสินใจ Voice Behavior)
- กล้องมุมมองบุคคลที่หนึ่ง
- ระบบ Discovery (เป็น Optional อยู่แล้ว)
- เอฟเฟกต์ขั้นสูง: Volumetric light, Lens flare, Portal/Elevator แบบเต็ม
- หลังบ้าน ฐานข้อมูล การเชื่อม AI จริง (งานเพื่อน)
- CI/CD และ Deploy (ทำหลังประกอบงาน)
- ปรับให้ใช้บนมือถือได้ดี (Desktop เป็นหลัก)

**ถือว่าล้มเหลวแม้จะ "ทำงานได้"**
- ข้อมูลตัวอย่างดูเหมือนข้อมูลจริง (ต้องเห็นชัดว่า "รอข้อมูล")
- เอฟเฟกต์บังข้อความ หรือเว็บกระตุกจนใช้ไม่ได้บนโน้ตบุ๊กทั่วไป
- ข้อความภาษาไทยแสดงผิด/เป็นกล่องสี่เหลี่ยม
- เพื่อนในทีมอ่านโค้ดแล้วอธิบายไม่ได้ (มีผลกับคะแนนเดี่ยว)
- ต่อหลังบ้านแล้วต้องรื้อหน้าเว็บ

## 6. โครงสร้างโลก

ใช้โครง 5 พื้นที่ตามที่เคยเสนอ เป็น **โครงชั่วคราว** เปลี่ยนชื่อ/ลด/เพิ่มได้ภายหลังจากไฟล์ตั้งค่า **[ข้อเสนอ]**

การเชื่อมต่อแบบ **Hub** **[ยืนยัน]**: Central Nexus เป็นศูนย์กลาง

```
                 [Project Dimension]
                         |
 [Arrival Gate] → [Central Nexus] — [Team HQ]
                         |
                   [AI Sanctuary]
```

- ทุกพื้นที่อยู่ในโลกเดียวกัน วางห่างกันในพิกัดต่างกัน กล้องบินจากที่หนึ่งไปอีกที่ = รู้สึกว่าเดินทางจริง **[ข้อเสนอ]**
- เรนเดอร์เฉพาะพื้นที่ปัจจุบันและพื้นที่ปลายทางระหว่างเดินทาง เพื่อประหยัดเครื่อง **[ข้อเสนอ]**
- สำรวจอิสระ (Freeguide **[ยืนยัน]**): ไปพื้นที่ใดก็ได้ทุกเวลาผ่าน Mini Map หรือประตูในฉาก ไม่บังคับเส้นทาง
- พื้นที่ปัจจุบันผูกกับ URL hash (เช่น `#/projects`) ปุ่ม Back ของเบราว์เซอร์ใช้ได้ แชร์ลิงก์ตรงไปพื้นที่ได้ **[ข้อเสนอ]**

### 6.1 การเดินทางระหว่างพื้นที่
- รอบแรก: กล้องบินแบบ Cinematic + แสงวาบตอนถึง (ประมาณ 1.5–2 วินาที) ใช้กับทุกเส้นทาง **[ข้อเสนอ]**
- รอบถัดไป: เพิ่ม Portal และ Elevator ตาม Scene Transition: Hybrid **[ยืนยัน แนวคิด / ทำรอบถัดไป]**
- ระหว่างเดินทางกดซ้ำไม่ได้ (กันกล้องสับสน)

### 6.2 กล้อง
- Cinematic: Intro และการเดินทาง **[ยืนยัน]**
- ในแต่ละพื้นที่: กล้องมุมคงที่ ขยับตามเมาส์เล็กน้อยให้มีมิติ **[ข้อเสนอ]**
- Fixed Showcase: ตอนดูโปรเจกต์ กล้องซูมเข้าหาชิ้นงาน **[ยืนยัน]**
- First-person: รอบถัดไป

## 7. รายละเอียดแต่ละพื้นที่ (รอบแรก)

### Arrival Gate + Intro
- Intro Cinematic 4–5 วินาที **[ยืนยัน]**: โหลดทรัพยากร + กล้องเคลื่อนผ่านเมืองนีออน + ชื่อเว็บ (ใช้ข้อความ "ชื่อกลุ่ม — รอข้อมูล" ชั่วคราว)
- มีปุ่ม Skip **[ข้อเสนอ]**
- จบ Intro แสดงปุ่ม "เข้าสู่จักรวาล / Enter" → บินไป Central Nexus
- ปุ่ม Enter เป็นจุดเริ่มเสียงในอนาคต (เบราว์เซอร์ต้องการการคลิกก่อนเล่นเสียง)
- กลับมาที่ Arrival Gate ภายหลัง: ไม่เล่น Intro เต็มซ้ำ แสดงฉากประตูทางเข้าพร้อมปุ่มไป Nexus **[ข้อเสนอ]**
- เปิดลิงก์ตรงเข้าพื้นที่อื่น (เช่น `#/projects`): เล่น Intro ก่อน แล้วพาไปพื้นที่นั้นแทน Nexus **[ข้อเสนอ]**

### Central Nexus (Hub)
- ลานกลางมีประตู 3–4 บานติดป้ายนีออนชื่อพื้นที่ คลิกประตู = เดินทาง
- AI ร่าง Energy Orb ลอยอยู่ คลิก = เปิดแชท
- Guide สำหรับผู้มาครั้งแรก **[ยืนยัน: Freeguide]**: กล่องคำแนะนำสั้น 2–3 ขั้น (นี่คือ Hub / ใช้ Mini Map / คุยกับ AI ได้ทุกที่) ปิดได้ และไม่แสดงซ้ำเมื่อกลับมาอีก **[ข้อเสนอ]**

### Project Dimension
- หอจัดแสดง: แท่นวางชิ้นงาน 1–3 แท่น ตามจำนวนในไฟล์ข้อมูล **[ยืนยัน: 1–3]**
- บนแท่นมีวัตถุ Hologram หมุนช้า ๆ
- คลิกแท่น → กล้องซูมเข้า (Fixed Showcase) → เปิด **Project Detail Panel** **[ข้อเสนอ]**
- ช่องข้อมูลใน Panel (Complete **[ยืนยัน]**): ชื่อ, สรุป, ปัญหาที่แก้, ฟีเจอร์หลัก, Tech Stack, Architecture (ข้อความ/รูป), รูปภาพ, ลิงก์ Demo, ลิงก์ GitHub, สมาชิกที่เกี่ยวข้อง — ทั้งหมดแสดง "รอข้อมูล"
- ลิงก์ที่ยังว่างจะกดไม่ได้และขึ้นว่ารอข้อมูล
- AI ร่าง Geometric Entity

### Team Headquarters (Basic **[ยืนยัน]**)
- ส่วนกลุ่ม: ชื่อกลุ่ม, แนวคิด, จุดเด่น
- ส่วนสมาชิก: การ์ด 3 ใบ (ทีมมี 3 คน **[ยืนยัน]**) — รูป, ชื่อ, บทบาท, ทักษะ, ผลงาน — ทั้งหมด "รอข้อมูล" รูปเป็นภาพเงาว่าง
- ส่วนติดต่อ (Contact): รายการช่องทางติดต่อ "รอข้อมูล" — วางไว้ที่ Team HQ และเปิดได้จากปุ่มบน HUD ด้วย **[ข้อเสนอ]**
- ฉากเป็นอาคาร/ห้องวิจัย ข้อมูลแสดงเป็น Panel HTML ซ้อนฉาก (อ่านง่าย รองรับภาษาไทยเต็มที่)

### AI Sanctuary
- พื้นที่นามธรรม ดิจิทัล เงียบสงบ
- AI ร่าง Fluid Entity ขนาดใหญ่ตรงกลาง
- แชทเปิดในโหมดเต็ม (กว้างกว่าในพื้นที่อื่น) **[ข้อเสนอ]**

### ร่าง AI ต่อพื้นที่ **[รอ: ยืนยัน Mapping]**
ใช้ Mapping ที่เสนอไว้ชั่วคราว: Nexus = Orb, Project = Geometric, Sanctuary = Fluid, Arrival Gate และ Team HQ = Orb ขนาดเล็ก ตั้งค่าในไฟล์เดียว เปลี่ยนได้ทันที รอบแรกทำทั้ง 3 ร่างแบบเรียบง่าย ร่าง AI มีสถานะ "กำลังคิด" (เต้น/สว่างขึ้น) ตอนรอคำตอบในแชท

## 9. Chat UI

- Panel ลอยด้านขวา สไตล์หน้าต่างเกม Cyberpunk (กรอบเรืองแสง พื้นโปร่งแสง) **[ข้อเสนอ]**
- แสดงข้อความ User / AI แยกฝั่งชัดเจน **[ยืนยัน]**
- ช่องพิมพ์ + ปุ่มส่ง (Enter ส่ง, Shift+Enter ขึ้นบรรทัด)
- ระหว่างรอคำตอบ: แสดงสถานะกำลังคิด + ร่าง AI ในฉากตอบสนอง
- ใต้ข้อความ AI: รายการแหล่งอ้างอิง (ชื่อ + ลิงก์) ถ้ามี **[ยืนยัน: ต้องแสดง references]**
- ข้อผิดพลาด (หลังบ้านล่ม/หมดเวลา): ข้อความแจ้งเป็นภาษาที่เลือก + ปุ่มลองใหม่
- ประวัติข้อความคงอยู่ระหว่างเปลี่ยนพื้นที่ แต่รอบแรกยังไม่ดึงประวัติกลับมาเมื่อรีเฟรชหน้า (ต้องมีช่องทางดึงประวัติจากหลังบ้านก่อน) **[ข้อเสนอ]**
- ส่งภาษาที่เลือกและพื้นที่ปัจจุบันไปให้หลังบ้านด้วย เพื่อให้ AI ตอบเป็นภาษาที่ถูกและปรับบุคลิกตามฉากได้

### 9.1 การเชื่อมหลังบ้าน

#### หลังบ้านที่มีอยู่แล้ว (`my-ai-chatbot/BE`, ตรวจเมื่อ 2026-11-16)

Express + TypeScript, Gemini ผ่าน endpoint แบบ OpenAI-compatible, ฐานข้อมูล SQLite, Deploy ที่ Render
(`https://my-ai-chatbot-api-b7qv.onrender.com`)

```
POST /messages        { text }            → 201 { userMessage, assistantMessage }
                                             (Message = { id, role: "user"|"assistant", text })
GET  /messages                            → Message[]   (ทุกข้อความของทุกคน)
PUT  /messages/:id    { text }            → Message
DELETE /messages/:id                      → { message: "deleted" }
DELETE /messages                          → { message: "cleared" }
Error                                      → { error } (400 / 429 / 502)
```

**หน้าเว็บใหม่จะใช้ได้กับหลังบ้านนี้ทันที** ผ่าน `POST /messages` **[ข้อเสนอ]**
- ไม่โหลด `GET /messages` มาแสดง เพราะตอนนี้เป็นประวัติรวมของผู้เข้าชมทุกคน แสดงเฉพาะข้อความของการเข้าชมครั้งนี้
- ไม่มีปุ่มแก้ไข/ลบข้อความ (ไม่อยู่ในโจทย์ และจะไปลบข้อความของคนอื่นในฐานข้อมูลรวม)
- อ่านช่อง `sources`, `sessionId` ถ้าหลังบ้านส่งมา ถ้าไม่มีก็แสดงแบบไม่มีแหล่งอ้างอิง
- URL หลังบ้านตั้งผ่าน `VITE_API_URL` ไม่ฝังในโค้ด
- Render แบบฟรีหลับเมื่อไม่มีคนใช้ คำขอแรกอาจช้า 30–60 วินาที → ตั้ง timeout ยาวพอ และแสดงข้อความ "กำลังปลุกระบบ AI" ถ้ารอนาน

#### โหมดจำลอง
ถ้าไม่ได้ตั้ง `VITE_API_URL` → ตอบข้อความตัวอย่างพร้อมแหล่งอ้างอิงตัวอย่าง (มีป้าย "โหมดจำลอง") ใช้ตอนพัฒนาฉากโดยไม่ต้องรันหลังบ้าน

#### สิ่งที่เสนอให้เพื่อนเพิ่มในหลังบ้าน (ไม่ขวางหน้าเว็บรอบแรก) **[ข้อเสนอ]**
ขยาย `POST /messages` แบบไม่ทำของเดิมพัง:

```
POST /messages
Request:  { text, sessionId?, language?: "th"|"en", district? }
Response: { userMessage, assistantMessage, sessionId, sources?: [ { title, url|null } ] }
```

รูปแบบเดิมที่เสนอไว้ก่อนตรวจหลังบ้าน (เก็บไว้อ้างอิง ไม่ใช้แล้ว):

```
POST {VITE_API_URL}/api/chat
Request:
{
  "sessionId": "string | null",   // null = เริ่มบทสนทนาใหม่
  "message":   "string",
  "language":  "th" | "en",
  "district":  "nexus" | "projects" | "team" | "sanctuary" | "gate"
}

Response 200:
{
  "sessionId": "string",
  "reply":     "string",
  "sources":   [ { "title": "string", "url": "string | null" } ]
}

Response error (4xx/5xx):
{ "error": "string" }
```

- `url` เป็น null ได้ สำหรับแหล่งอ้างอิงภายใน เช่น "ข้อมูลโปรไฟล์ทีม"
- หลังบ้านต้องเปิด CORS ให้โดเมนของหน้าเว็บ
- เก็บ `sessionId` ไว้ในเบราว์เซอร์ เพื่อให้หลังบ้านเก็บประวัติลง PostgreSQL ต่อเนื่องได้

## 10. ข้อมูลและภาษา

- ข้อมูล Portfolio ทั้งหมดอยู่ที่ `src/data/portfolio.ts` ไฟล์เดียว: กลุ่ม, สมาชิก, โปรเจกต์, ช่องทางติดต่อ
- ข้อความทุกช่องมีทั้ง `th` และ `en`
- ทุกรายการที่ยังไม่มีข้อมูลจริงมี `placeholder: true` → หน้าเว็บแสดงป้าย "รอข้อมูล / Awaiting data" ให้เห็นชัด
- รูปภาพวางที่ `public/images/` อ้างอิงจากไฟล์ข้อมูล
- ข้อความหน้าเว็บ (ปุ่ม, หัวข้อ, Guide) อยู่ที่ `src/i18n/th.ts` และ `src/i18n/en.ts`
- ข้อความภาษาไทยทั้งหมดแสดงเป็น HTML ซ้อนฉาก ไม่ใช้ข้อความ 3D (ฟอนต์ 3D รองรับภาษาไทยไม่ดี) ข้อความ 3D ในฉากใช้กับป้ายนีออนภาษาอังกฤษ/ตัวอักษรตกแต่งเท่านั้น

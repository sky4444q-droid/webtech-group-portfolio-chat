# เก็บรายละเอียดกราฟิก รอบ 2: มุมมองกว้าง ควัน ไฟตึก และหน้าแรก

วันที่: 2026-11-17 · กิ่ง: `feature/vu-round3` · ต่อจาก `2026-11-17-graphics-overhaul-design.md`

## 1. เป้าหมายและเหตุผล

ผู้ใช้ดูผลรอบที่แล้วแล้วบอก 4 เรื่อง

1. อยากให้มุมมองกว้างขึ้น
2. รายละเอียดเล็กน้อยยังไม่ดีพอ: ควัน
3. รายละเอียดเล็กน้อยยังไม่ดีพอ: ไฟตามตึก
4. โลโก้กับตัวหนังสือในหน้าหลักไม่กลมกลืนกัน

ผู้ใช้เห็นว่าทำให้สวยกว่านี้ได้ และเลือกเองว่าชื่อ NEXORA มุมซ้ายบนให้เปลี่ยนจากสีแดงเป็นม่วงอมชมพู

สิ่งที่พบจากการเปิดเว็บจริงที่ 1440×860:

- **มุมกล้อง:** จุดชมเกือบทุกจุดเป็นระดับสายตา (สูง 1.7 ม.) และมองกว้างแค่ 55° เข้า Central Nexus แล้วเห็นแต่ผนังตึกสองข้าง เหมือนยืนในซอก
- **ควัน:** มีแค่ `GroundFog` ทึบ 9% แทบมองไม่เห็น ไม่มีควันหรือไอน้ำเลย
- **ไฟตึก:** `curtainWallTexture()` สุ่มเปิดไฟ 35% แบบอิสระทีละช่อง สีน้ำตาลอุ่น ฟ้า หรือบานเย็น แต่ละช่องเป็นสี่เหลี่ยมทึบเรียบ ตัวตึกเกือบดำ ไกล ๆ จึงดูเหมือนกระเบื้องสีลอยอยู่ นอกจากนี้ texture เป็นแผ่นเดียวกันทุกตึก (8×16 ช่อง) จึงเห็นลายซ้ำ
- **หน้าแรก (`Intro`):**
  - โลโก้สีม่วง ชมพูม่วง เงิน แต่ "NEXORA" เป็น Orbitron สีขาว มีเงาแยกสีฟ้ากับชมพูแบบกลิตช์
  - แถบโหลดไล่ม่วงไปฟ้า ปุ่มไล่ชมพูแดงไปม่วง
  - ข้อความเล็กด้านบนเป็นภาษาไทย 12px ห่างตัวอักษร 0.5em อ่านยาก
  - ทั้งหมดวางบนฉากเมืองที่ยุ่งตรง ๆ
  - รูป `nexora-emblem.png` มีลายตารางจาง ๆ ติดในขอบเรือง
- **HUD หลังเข้าเมือง:** ชื่อ NEXORA และเส้นเน้นต่าง ๆ ใช้ `--red: #ff1f3d` ซึ่งไม่เข้ากับโลโก้สีม่วง

## 2. ขอบเขต

**ทำ**

- มุมมองกว้างขึ้นทุกจุดชม
- ไอน้ำและควันที่มีแหล่งที่มา
- ไฟหน้าต่างที่ดูเป็นตึกมีคนอยู่
- หน้าแรกและ HUD ใช้ภาษาภาพชุดเดียวกับโลโก้

**ไม่ทำ**

- ไม่เพิ่มคน
- ไม่เปลี่ยนเนื้อหา ข้อมูลทีม หรือข้อความ
- ไม่เปลี่ยนวิธีควบคุม (ใช้เมาส์อย่างเดียวตามเดิม)
- ไม่แก้งานค้างเล็ก ๆ จากรอบก่อน (หลังคายื่น ฯลฯ) ยกเว้นงานที่ทับไฟล์เดียวกันและแก้ได้ในบรรทัดเดียว

**ถือว่าล้มเหลว** ถ้าเกิดข้อใดข้อหนึ่ง

- fps ต่ำกว่างบ
- ข้อความบนการ์ดโฮโลหรือจอข้อมูลล้นจอหรืออ่านไม่ออกเพราะเล็กลง
- ควันกลายเป็นม่านเทาทับป้าย
- ไฟตึกสว่างจนแย่งความเด่นของป้ายนีออน

## 3. ข้อกำหนดที่ยังใช้ทั้งหมด

- ห้ามแตะ `BE/` และห้ามใส่ API key
- commit ในเครื่องเท่านั้น push เมื่อผู้ใช้สั่ง ห้าม commit `FE/tsconfig.tsbuildinfo`
- asset ต้องเป็น CC0 และลงใน CREDITS รวมไม่เกิน 8 MB งานนี้ตั้งใจสร้างทุกอย่างด้วย shader และ canvas ไม่โหลดไฟล์ใหม่
- `EffectComposer` ใช้ `multisampling={0}`, dpr คง `[1,1]`
- ตัวจิ๋วใช้สัญลักษณ์หกเหลี่ยม
- logic การวางของเป็นโมดูล `.ts` ล้วนที่มี unit test ส่วน R3F ใช้ instanced mesh ชนิดละ 1 draw call
- RNG ของงานใหม่แยกจาก RNG เดิม เพื่อไม่ให้ตำแหน่งของเดิมขยับ
- แพตช์ shader ต้องทำก่อน compile ครั้งแรก (สร้างใน `useMemo` แล้วต่อด้วย `<primitive attach="material">`)
- Windows ไม่แยกตัวพิมพ์เล็กใหญ่ของชื่อไฟล์ ชื่อไฟล์ใหม่ต้องไม่ชนกับไฟล์เดิมเมื่อไม่สนตัวพิมพ์

## 4. ทางเลือกที่พิจารณา

**มุมมองกว้าง**

- **(ก) เพิ่ม fov อย่างเดียวเป็น 68–70°:** ง่ายที่สุด แต่ที่ระดับสายตา ขอบภาพจะยืด และของตรงกลางเล็กลงมาก
- **(ข) เพิ่ม fov เป็นประมาณ 65° แล้วถอยหลังและยกจุดชมขึ้นเล็กน้อยทีละจุด** ← **เลือก (เป็นการตัดสินใจของผม):** ได้ภาพกว้างโดยไม่ยืด ของสำคัญยังใหญ่พอ แลกกับต้องจูนทีละจุดและเทสต์ขนาดการ์ด
- **(ค) ยกกล้องเป็นมุมสูงแบบเดิม:** ขัดกับรูปตัวอย่างแรกที่ผู้ใช้ชอบ (มุมเดินถนนระดับสายตา) จึงไม่เลือก

**ควัน**

- **(ก) แผ่นหมอกใหญ่หลายชั้น:** เปลืองพิกเซลมาก (ฉากนี้ช้าที่การวาดพิกเซลอยู่แล้ว) และดูเป็นม่านแบน
- **(ข) กลุ่มอนุภาคไอน้ำเล็ก ๆ ที่มีแหล่งที่มา** (ช่องระบายบนถนน ปล่องบนหลังคา) วาดเป็น billboard โปร่งแสงที่ใช้ shader สร้างลายควัน instanced ครั้งเดียว ← **เลือก (ตัดสินใจเอง):** ตรงกับหลักของรอบที่แล้วว่า "แสงและของในฉากต้องมีที่มา"
- **(ค) volumetric raymarch:** สวยแต่หนักเกินงบ fps

**ไฟตึก**

- **(ก) วาด canvas ใหม่อย่างเดียว:** แก้เรื่องสีกับลาย แต่ยังซ้ำกันทุกตึกและไม่มีชีวิต
- **(ข) วาด canvas ใหม่ + ใน shader ของ `patchWindowUv` เลื่อนลายตามแต่ละตึก (hash จากตำแหน่ง instance) + ให้บางช่องเปิดปิดช้า ๆ ตามเวลา** ← **เลือก (ตัดสินใจเอง)**

**หน้าแรกกับ HUD:** มีทางเดียวที่เหมาะสม คือยึดสามสีแบรนด์ใน `config/brand.ts` (ม่วง `#8B5CF6`, ชมพูม่วง `#D946EF`, เงิน `#C0C4D0`) เป็นสีหลักของ UI ทั้งหมด ผู้ใช้เลือกแล้วว่าชื่อมุมซ้ายบนเป็นม่วงอมชมพู

## 5. การออกแบบ

### 5.1 มุมมองกว้าง

- ย้าย fov ไปเป็นค่าคงที่เดียวชื่อ `CAMERA_FOV` ใน `config/` แล้วให้ `World.tsx` และเทสต์ใช้ค่านี้ร่วมกัน
  - ค่าเริ่มที่ **65°** ผู้สร้างปรับได้ในช่วง 62–68° ถ้าภาพจริงดีกว่า
  - เลิก hard-code `55` ในเทสต์
- ทุกจุดชมใน `VIEWPOINTS` ถอยกล้องหลังและยกขึ้นเล็กน้อยในทิศตรงข้ามกับ `target`
  - แนวทาง: ถอย 2–4 ม. ความสูงระดับสายตาเป็น 1.9–2.4 ม.
  - ถอยได้เท่าที่ไม่ทะลุตึก ผนังล็อบบี้ หรือของในฉาก ผู้สร้างตรวจจากภาพจริงทีละจุด
  - วงแหวนที่คลิก (`marker`) ต้องยังอยู่ในจอและไม่ทับตัวจิ๋ว
- `lookRange` ของจุด eye คงเดิม (±25°) ยกเว้นที่มุมกว้างขึ้นแล้วทำให้หันไปเห็นช่องว่างนอกเมือง
- `teamHoloCamera()` ต้องยังทำให้การ์ดทีมพอดีจอที่กว้าง 736px ขึ้นไปตามเทสต์เดิม (ใช้ fov ใหม่) และตัวหนังสือบนการ์ดต้องไม่เล็กกว่าเดิมจนอ่านยาก ถ้าเล็กลงให้ลด `TEAM_HOLO_DISTANCE`
- ท่ากล้องตอนดูผลงานใน Projects และระหว่างเดินทาง (`CameraRig`) ต้องยังเห็นของสำคัญเต็มตา
- จุดชมแรกของทุกเขตต้องยังเห็นหอ Energy Core ในจอตามเทสต์ NDC ใน `skylineLayout.test.ts` ซึ่งตอนนี้ hard-code `PerspectiveCamera(55, …)` อยู่ ต้องเปลี่ยนให้ใช้ `CAMERA_FOV` และใช้ท่ากล้องจาก `viewpointWorld` จริง

### 5.2 ไอน้ำและควัน

- **โมดูลวางตำแหน่ง** `world/fx/steamLayout.ts` (logic ล้วน มีเทสต์) คืนรายการแหล่งควัน `{ kind, position, radius, height, tint }`
  - **ช่องระบายบนถนน (`vent`):** ถนนละ 3–4 จุด อยู่บนพื้นถนน ไม่อยู่บนทางเดินของตัวจิ๋ว ไม่อยู่ใต้วงแหวนจุดชม และไม่อยู่หน้ากล้องในระยะ 3 ม. ของจุดชมใด ๆ
  - **ปล่องบนหลังคา (`stack`):** 6–10 จุดบนยอดตึกริมถนนและตึกไกล ใช้ข้อมูลหลังคาจาก `kitLayout` / `skylineLayout`
  - **สี (`tint`):** มาจากแหล่งแสงที่ใกล้ที่สุดในระยะ 8 ม. (ป้าย จอ ไฟถนน) ถ้าไม่มีให้ใช้สีหมอกเมือง
  - ใช้ RNG แยกของตัวเอง
- **ภาพ** `world/fx/Steam.tsx`: billboard แบบ instanced ครั้งเดียว ใช้ shader ลายควันจาก noise ที่ม้วนขึ้นช้า ๆ
  - ขอบนุ่ม จางตามความสูง โปร่งแสงแบบ normal blending (ไม่ใช่ additive เพราะแผ่นใหญ่ + Bloom ทำให้ภาพดำ)
  - `depthWrite={false}` และใช้ fog
  - แต่ละแหล่งมี 4–8 แผ่นวนรอบอายุ
  - ขนาดแผ่นต้องเล็กพอให้ไม่บังป้ายหลัก
  - ช่องระบายส่องแสงอ่อน ๆ จากใต้พื้นได้ ใช้เป็นแผ่น spill เล็กแบบเดียวกับ `LightSpill`
- **หมอกพื้น:** ทำ `GroundFog` ให้เห็นได้จริงเฉพาะบริเวณใต้แหล่งไฟ ใช้ร่วมกับตำแหน่งจาก `lightSpill` หรือเพิ่มความทึบแบบจำกัดวง โดยไม่ทำให้ทั้งพื้นเป็นม่านเทา
- **การเปิดปิด:** ใช้ flag ใหม่ `steam` ใน `fxEnabled` เปิดเฉพาะโหมดสูง
- **งบ:** ทั้งหมดรวมไม่เกิน 2 draw call (`Steam` + spill ของช่องระบาย) และจำนวนแผ่นที่เห็นพร้อมกันไม่เกินประมาณ 120

### 5.3 ไฟตามตึก

**วาด `curtainWallTexture()` ใหม่ (ยังเป็น 8×16 ช่อง ช่องละ 1.3 × 3.3 ม.)**

- **เปิดไฟเป็นกลุ่มตามชั้น:** แต่ละชั้นสุ่มสถานะก่อน (เปิดทั้งชั้น เปิดครึ่งชั้น หรือดับเกือบทั้งชั้น) แล้วค่อยสุ่มช่องในชั้นนั้น
  - ภาพรวมเปิดไฟประมาณ 30–40%
- **สีไฟ:** ส่วนใหญ่ขาวอุ่นกับขาวเย็น สีอื่นมีแค่ประมาณ 5% และใช้โทนแบรนด์
  - เลิกสุ่มสีบานเย็น 15% แบบเดิม
- **ในช่องที่เปิดไฟ:** แสงไล่ระดับ สว่างตรงเพดาน จางลงข้างล่าง มีเงามู่ลี่หรือเงาของในห้องบางช่อง และมีกรอบเห็นชัด
- **กระจกที่ดับ:** สีน้ำเงินเข้มที่มีแสงไล่ระดับจาง ๆ ให้ดูเป็นกระจก ไม่ใช่ช่องดำ
- **แถบพื้นชั้นกับเสา:** ยังเป็นสีดำ แต่บางตึกมีแถบไฟ LED บาง ๆ ตามแนวพื้นชั้น เป็นช่องพิเศษในแผ่น texture

**ใน `patchWindowUv`**

- **เลื่อนลายตามแต่ละตึก:** ใช้ hash จากตำแหน่งของ instance ให้แต่ละตึกเลื่อนลายไปคนละช่อง ตึกติดกันจะไม่ซ้ำกัน
- **ให้มีชีวิต:** ประมาณ 2–3% ของช่องเปิดปิดช้า ๆ (เปลี่ยนทุก 20–60 วินาที ไม่กะพริบเร็ว) คำนวณจาก hash ของช่อง + เวลา
  - ใช้ uniform เวลาตัวเดียว
  - ห้ามทำให้ภาพกะพริบตามเกณฑ์ `?debug=flicker`
- ใช้กับ material ตึกริมถนนใน `StreetKit` ส่วน `Skyline` ใช้ texture ใหม่ได้โดยไม่ต้องเปิดปิด
- ตึก Team (`TEAM_TOWER`) ไม่ได้แพตช์ shader ให้ใช้ texture ใหม่ตามเดิม

**ความสว่างโดยรวม:** ป้ายนีออนต้องยังเด่นกว่าหน้าต่างชัดเจน ถ้าตึกสว่างขึ้นให้ลด `emissiveIntensity`

### 5.4 หน้าแรกกับ HUD

**สีของ UI**

- เพิ่มตัวแปร CSS `--brand-purple`, `--brand-magenta`, `--brand-silver` ให้ค่าตรงกับ `config/brand.ts`
- เปลี่ยนการใช้ `--red` ใน HUD ไปเป็นโทนแบรนด์: ชื่อ NEXORA บรรทัดบอกที่อยู่ ปุ่มนำทาง ปุ่มคุยกับ AI กรอบ และเส้นเน้น
  - **[ตัดสินใจเอง]** ผู้ใช้เลือกเฉพาะชื่อมุมซ้ายบน แต่ถ้าเปลี่ยนชื่ออย่างเดียว ปุ่มและเส้นสีแดงรอบ ๆ จะชนกับชื่อ จึงเปลี่ยนทั้งชุด
  - ยังมีสีแดงในฉากได้ (ไฟท้ายรถ ไฟบนยอดตึก)

**กลุ่มโลโก้ในหน้าแรก (`Intro`)**

- โลโก้กับชื่อเป็นชุดเดียวกัน: "NEXORA" ไล่สีม่วง → ชมพูม่วง → เงินด้วย `background-clip:text` และมีแสงเรืองนุ่ม ๆ สีม่วงเท่ากับโลโก้
  - เลิกเงาแยกสีฟ้ากับชมพู ถ้าจะมีกลิตช์ ให้เป็นการขยับสั้น ๆ ตอนปรากฏครั้งแรกในโทนแบรนด์
  - ต้องเคารพ `prefers-reduced-motion`
- ข้อความเล็กด้านบนใช้ฟอนต์ไทยที่อ่านง่าย 13–14px ระยะห่างตัวอักษรไม่เกิน 0.15em สีเงิน
- เปอร์เซ็นต์โหลดใช้แนวเดียวกัน
- แถบโหลดและปุ่ม "เข้าสู่จักรวาล" ไล่สีม่วง → ชมพูม่วง
- มีเงามืดนุ่ม ๆ เป็นวงรีหลังกลุ่มโลโก้ ให้เด่นจากฉากเมืองโดยไม่บังเมืองทั้งจอ
- ซ่อนลายตารางจาง ๆ ในขอบเรืองของรูปโลโก้ด้วย `mask-image` แบบวงกลมนุ่ม (ไม่แก้ไฟล์รูป) ถ้า mask ตัดวงแหวนโลโก้ ให้ปรับเฉพาะความทึบของขอบแทน
- ลบกฎ CSS ที่ซ้อนทับกันท้ายไฟล์ เช่น `.intro-title { text-shadow:none !important }` และ `.intro-logo` ที่กำหนดสองที่ ให้เหลือที่เดียว

**HUD:** ชื่อ NEXORA มุมซ้ายบนใช้ฟอนต์และการไล่สีแบบเดียวกับหน้าแรก (ขนาดเล็กลง) วางคู่กับ `nexora-symbol.png` ให้ดูเป็นชุดเดียวกัน

**ต้องอ่านง่ายบนจอเล็ก:** ทุกอย่างต้องอ่านได้ที่ความกว้าง 375px

## 6. งบประสิทธิภาพและการตรวจ

- โหมดสูงไม่ต่ำกว่า **50 fps** ทุกเขต ทั้งที่จุดชมแรกและระหว่างเดินทาง (รอบก่อนวัดได้ 57.7–92.9 fps)
- โหมดต่ำไม่ต่ำกว่า **55 fps** บนเครื่องเดียวกัน
- วัดด้วย `?debug=perf` และแนบตัวเลขก่อน/หลัง
  - มุมกว้างขึ้นทำให้มีของในจอมากขึ้น ต้องดู draw call ด้วย
- `?debug=flicker` ต้องได้ 0 พิกเซลที่กะพริบ
- เทสต์ทั้งหมดผ่าน และ build ผ่าน
- ถ่ายภาพก่อน/หลังที่ 1440×860 ของหน้าแรก, Central Nexus, Projects, Team และ Sanctuary

## 7. สิ่งที่ให้ผู้สร้างตัดสิน

- ค่า fov สุดท้ายในช่วง 62–68° และระยะถอยของแต่ละจุดชม (ตรวจจากภาพจริง)
- จำนวนแผ่นต่อแหล่งควัน รูปแบบ noise และความเร็ว
- รูปแบบเงาในหน้าต่าง (มู่ลี่ ต้นไม้ ชั้นวาง) ขอให้เป็นลายทั่วไป ไม่มีตัวหนังสือหรือคน
- ความเข้มของแสงเรืองในหน้าแรกและ HUD
